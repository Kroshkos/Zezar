# Инструкция руководителя подразделения (HEAD) — «ЦЕЗАРЬ»

Роль **Руководитель (HEAD)** управляет одним (или несколькими) рабочими
пространствами: набором людей, модулями, справочниками, шерингом и потоком задач
своего подразделения. Координатор/админ видит вас «сверху» и может помогать.

---

## 1. Вход в систему

Единственный контур входа — **логин и пароль** (авторизация через Яндекс ID из
системы удалена). Учётную запись и роль создаёт администратор; при первом входе
система потребует сменить пароль. Подробно о входе —
[INSTRUCTION_USER.md](INSTRUCTION_USER.md), п. 1.

После входа в сайдбаре вашего пространства появляется раздел
**«⚙️ Администрирование»** — ваша основная зона управления.

Если вы руководитель нескольких подразделений, переключатель пространств доступен
вверху; все ваши пространства перечислены на вкладке «Подразделения» админ-раздела.

## 2. Создание задач/проектов в своём пространстве

* Кнопка **«+»** в разделах Задачи / Проектная работа / Совещания и доп. модули.
* Пространство выбирается из списка **ваших** подразделений — явный выбор своего
  пространства руководителю разрешён (ошибка «выбор чужого пространства доступен
  только админу/координатору» появляется только при попытке выбрать пространство,
  где вы не состоите).
* Поля карточки: название, описание, статус, приоритет, срок, теги, ответственный.
* Ответственный — сотрудник вашего пространства; при шеринге сущности на другое
  подразделение тот отдел назначает **своего** ответственного (правило: не более
  одного ответственного от каждого участвующего подразделения).
* Редактировать/закрывать карточку можно из списка или из её страницы; все
  действия попадают в журнал событий.

## 3. Администрирование подразделения

Раздел «⚙️ Администрирование» доступен только HEAD своих пространств и
ADMIN/COORDINATOR. Вкладки:

| Вкладка | Действия |
|---|---|
| 🏢 Подразделения | Список ваших пространств, создание нового рабочего пространства (при наличии прав), переименование, настройки |
| 📋 Обзор | Сводка: состав, включённые модули, последние шеринги, учётные записи, события |
| 👥 Участники | Добавить существующего пользователя в пространство (поиск по кандидатам); **назначить роль в пространстве**: Руководитель / Участник; исключить участника |
| 🧩 Модули | Включать/выключать дополнительные модули пространства: 📄 Документы, 💻 ПО и разработки, 💰 Гранты, 🎓 Стипендии, 🎯 Приоритеты (базовые — Дашборд, Задачи, Проектная работа, Совещания, Администрирование — отключить нельзя) |
| 📚 Справочники | Наборы статусов, приоритетов и типов сущностей пространства: добавить/переименовать/удалить пункт |
| 🔗 Шеринг | Активные расшаривания сущностей вашего пространства и входящие запросы |
| 🔔 Уведомления | Сценарии Telegram-рассылки по пространству (вкл/выкл шаблонов) |
| 📜 Журнал | Локальный аудит: кто и когда что менял в пространстве |

### Смена ролей в пространстве

* Повышение **Участник → Руководитель** доступно сразу: во вкладке «Участники»
  выберите роль в выпадающем списке сотрудника — изменение применяется
  немедленно.
* Понижение **Руководитель → Участник**: система не даст понизить, если в
  пространстве после понижения **не останется ни одного руководителя** — появится
  сообщение «В подразделении должен остаться хотя бы один руководитель». Сначала
  назначьте руководителем другого сотрудника, затем понижайте себя/прежнего.
* Глобальная роль пользователя (Участник/Координатор/Админ) меняется только в
  **общей админке** (`/admin`) и доступна только ADMIN. Роль в пространстве и
  глобальная роль — разные вещи. После смены роли страница обновляется и права
  применяются немедленно.

## 4. Шеринг сущностей между пространствами

На карточке сущности → «Поделиться» → выбрать отдел-получатель и уровень доступа:

* **READ** — другой отдел видит карточку без изменений;
* **EDIT** — может редактировать и комментировать поток;
* **FULL** — полный доступ: перешеринг и назначение ответственных со стороны
  получателя.

Изоляция: другие пространства **не видят** ваши сущности, пока вы их не расшарили.

## 5. Контроль потока

* Дашборд руководителя — агрегированная сводка по всему подразделению: просрочки,
  статусы, загрузка сотрудников, ближайшие совещания.
* Область Telegram-уведомлений и календарной синхронизации для HEAD — всё
  подразделение (участник видит только своё).
* Журнал событий («📜») — полный след изменений: удобно разбирать спорные ситуации.

## 6. Интеграции участников

* Telegram: участники привязываются сами (страница «Интеграции», `/start <код>`);
  руководитель получает сводки по всему пространству.
* Яндекс.Календарь: участник подключает app-пароль самостоятельно; задачи и
  совещания, где он ответственный, уходят в его личный календарь «Цезарь».
  Отключить синхронизацию участник может сам кнопкой «Отключить».

## 7. Частые ситуации

| Ситуация | Решение |
|---|---|
| «Выбор чужого пространства…» при создании задачи | Так было раньше: система ошибочно блокировала и выбор своего пространства. Исправлено — теперь ошибка появляется только если выбрано пространство, где у вас нет членства: выберите своё из списка |
| Не понижается роль руководителя | В пространстве должен остаться другой HEAD — сначала назначьте нового |
| Сотрудник не видит раздел | Включите ему модуль во вкладке «Модули» |
| Нет нужного статуса/приоритета в форме | Добавьте значение во вкладке «Справочники» |
| Нужно создать задачу в чужом пространстве | Обратитесь к координатору/админу |
| Нельзя исключить последнего руководителя из состава | Система требует ≥1 HEAD: сначала назначьте нового руководителя |
| Изменили мою роль, но я вижу старые права | Обновите страницу (F5) — права применяются немедленно после перезагрузки |
