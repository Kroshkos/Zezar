# Инструкция координатора (COORDINATOR) — «ЦЕЗАРЬ»

Роль **Координатор** — работа поперёк всех рабочих пространств: агрегированный
дашборд группы «Координаторы», видимость и редактирование сущностей во всех
подразделениях, помощь руководителям. Без управления пользователями и глобальными
ролями (это зона администратора).

---

## 1. Вход и главная страница

Единственный контур входа — **логин и пароль** (авторизация через Яндекс ID
удалена из системы). Учётную запись с ролью «Координатор» создаёт администратор;
при первом входе потребуется сменить пароль.

После входа доступен **агрегированный дашборд**: сводка по всем пространствам —
задачи, проекты, совещания, гранты и т.д. с фильтрами по подразделению, статусу,
приоритету, сроку.

## 2. Что доступно координатору

| Возможность | Комментарий |
|---|---|
| Видеть все сущности всех пространств | Включая нерасшаренные — пространство не изолируется от координатора |
| Создавать/редактировать в любом пространстве | В форме создания **можно выбрать любое пространство** (руководителю — только свои) |
| Управлять составом и модулями любого пространства | Как руководитель — через «⚙️ Администрирование» → вкладки «Участники», «Модули», «Справочники» |
| Назначать роли в пространстве (HEAD/MEMBER) | Но **не глобальные** роли (ADMIN/COORDINATOR меняет только админ) |
| Шеринг сущностей между пространствами | READ / EDIT / FULL |
| Telegram/Календарь — область «вся система» | Сводки по всем подразделениям |

Инварианты, которые проверяются системой (в том числе при понижении роли):

* в каждом подразделении должен остаться хотя бы один руководитель (HEAD);
* не более одного ответственного от каждого участвующего подразделения.

## 3. Типовые операции

**Создать задачу руководителю в его пространстве:** раздел «Задачи» → «+» →
в селекте пространства выбрать нужное подразделение → заполнить карточку.

**Добавить человека в пространство:** «⚙️ Администрирование» → «Подразделения» →
выбрать пространство → «Участники» → «Добавить участника» (поиск среди уже
созданных учётных записей). Если учётной записи нет — попросите администратора
её создать.

**Перенести человека между пространствами:** в новом — добавить; в старом —
исключить.

**Назначить/снять руководителя пространства:** «Участники» → селект роли →
применяется немедленно (страница обновляет состояние сама).

**Включить модуль пространству:** «Администрирование» → «Модули» → тумблер.

**Настроить справочник пространства:** «Администрирование» → «Справочники» →
добавить/переименовать статусы, приоритеты, типы.

**Расшарить сущность между отделами:** на карточке → «Поделиться» → выбрать
отдел-получатель и уровень (READ / EDIT / FULL).

## 4. Отличия от администратора

Координатор **не может**: создавать/блокировать/удалять пользователей, менять
глобальную роль (admin/coordinator/member), сбрасывать пароли, видеть системный
аудит `/admin/events` и настройки окружения. При необходимости — к администратору
([INSTRUCTION_ADMIN.md](INSTRUCTION_ADMIN.md)).

## 5. Частые ситуации

| Ситуация | Решение |
|---|---|
| Не открывается вкладка общей админки (`/admin`) | Это зона ADMIN, обратитесь к администратору |
| Понижение HEAD не применяется | Система требует оставить в пространстве другого руководителя — интерфейс покажет текст ошибки; сначала назначьте нового HEAD |
| Руководитель жалуется на «чужое пространство» | Раньше система ошибочно блокировала даже выбор **своего** пространства (исправлено). Если ошибка появляется сейчас — проверьте членство пользователя в этом пространстве («Участники»); при отсутствии членства добавьте его или создайте задачу сами, выбрав нужное пространство |
| Сотрудник ещё не имеет учётной записи | Создание пользователей — у администратора («Новый пользователь» + начальный пароль) |
| Роль в пространстве изменилась, а UI показывает старую | Обновите страницу; сервер перевыпускает сессионный cookie с новым epoch прав, поэтому рассинхрон исчезает после F5 |
